# سرویس همگام‌سازی سابسکریپشن پاسارگاد با GitHub (Subsync)

## معرفی پروژه

این پروژه یک سرویس پایتونی است که محتوای اشتراک (Subscription) پنل
**پاسارگاد** را به‌صورت خودکار و دوره‌ای در یک مخزن **GitHub** آینه
(mirror) می‌کند.

هدف اصلی این است که آدرس واقعی اشتراک پاسارگاد هرگز در دسترس
مشتریان قرار نگیرد. به جای آن، مشتریان فقط یک **GitHub Raw URL**
ثابت دریافت می‌کنند که همیشه آخرین کانفیگ‌ها را در خود دارد.

### جریان کار

```
آدرس اشتراک پاسارگاد
        ↓
سرویس همگام‌سازی پایتون (sync.py)
        ↓
GitHub REST API
        ↓
فایل unlimited.txt در مخزن گیت‌هاب
        ↓
GitHub Raw URL
        ↓
مشتریان
        ↓
v2rayNG / Hiddify / Clash / Streisand
```

هر بار که اسکریپت اجرا می‌شود:

1. محتوای فعلی اشتراک از پاسارگاد دانلود می‌شود.
2. محتوا از نظر معتبر بودن بررسی می‌شود (خالی نبودن، عدم خطای HTTP و ...).
3. فایل فعلی از گیت‌هاب خوانده می‌شود و هش SHA256 آن با نسخه جدید مقایسه می‌شود.
4. اگر تغییری وجود نداشته باشد، برنامه بدون هیچ درخواست نوشتنی به پایان می‌رسد.
5. اگر تغییر وجود داشته باشد، فایل روی گیت‌هاب از طریق **GitHub Contents API** به‌روزرسانی می‌شود.

هیچ‌کدام از مراحل بالا از `git clone`، `git commit` یا `subprocess`
استفاده نمی‌کند؛ تمام ارتباط با گیت‌هاب صرفاً از طریق درخواست‌های
HTTP به REST API انجام می‌شود.

## معماری پروژه

```
project/
├── README.md            # همین فایل
├── requirements.txt      # وابستگی‌های پایتون
├── .env.example          # نمونه متغیرهای محیطی
├── .gitignore
├── sync.py               # نقطه ورود اصلی برنامه
├── github_api.py         # کلاینت GitHub REST API
├── logger.py             # پیکربندی لاگ‌گیری
├── config.py             # خواندن و اعتبارسنجی تنظیمات از .env
├── utils.py              # توابع کمکی (هش، اعتبارسنجی، base64)
└── logs/                 # محل ذخیره فایل‌های لاگ
```

| فایل | مسئولیت |
|---|---|
| `config.py` | خواندن متغیرهای محیطی و ساخت شیء تنظیمات |
| `logger.py` | ساخت logger مشترک با خروجی کنسول و فایل |
| `utils.py` | محاسبه SHA256، اعتبارسنجی محتوا، تبدیل base64 |
| `github_api.py` | خواندن/نوشتن فایل در گیت‌هاب از طریق REST API |
| `sync.py` | هماهنگ‌کننده اصلی کل فرآیند (دانلود → مقایسه → آپلود) |

## پیش‌نیازها

- **Python 3.11 یا بالاتر**
- یک مخزن گیت‌هاب (عمومی یا خصوصی) برای نگهداری فایل `unlimited.txt`
- یک **GitHub Personal Access Token** با دسترسی نوشتن به همان مخزن
- دسترسی شبکه به آدرس اشتراک پاسارگاد

---

## نصب روی Ubuntu

```bash
# ۱. به‌روزرسانی سیستم
sudo apt update && sudo apt upgrade -y

# ۲. نصب پایتون ۳.۱۱ (در صورت نبود)
sudo apt install -y python3.11 python3.11-venv python3-pip

# ۳. انتقال پروژه به مسیر مورد نظر (مثلاً /opt/subsync)
sudo mkdir -p /opt/subsync
sudo cp -r ./project/* /opt/subsync/
cd /opt/subsync

# ۴. ساخت محیط مجازی
python3.11 -m venv venv
source venv/bin/activate

# ۵. نصب وابستگی‌ها
pip install --upgrade pip
pip install -r requirements.txt
```

## ساخت GitHub Personal Access Token

1. وارد حساب گیت‌هاب خود شوید.
2. به مسیر زیر بروید:
   `Settings → Developer settings → Personal access tokens → Fine-grained tokens`
3. روی **Generate new token** کلیک کنید.
4. مخزن مورد نظر (همان مخزنی که `unlimited.txt` در آن قرار می‌گیرد) را انتخاب کنید.
5. در بخش **Repository permissions**، دسترسی **Contents** را روی
   **Read and write** قرار دهید.
6. توکن ساخته‌شده را کپی کرده و در جایی امن نگه دارید — این توکن
   فقط یک‌بار نمایش داده می‌شود.

> **نکته امنیتی:** توکن را هرگز در کد، در پیام‌های چت یا در مخزن
> عمومی قرار ندهید. این توکن فقط باید داخل فایل `.env` (که در
> `.gitignore` قرار دارد) نگهداری شود.

## پیکربندی فایل .env

فایل `.env.example` را کپی کرده و به `.env` تغییر نام دهید:

```bash
cp .env.example .env
```

سپس مقادیر زیر را با اطلاعات واقعی خود پر کنید:

```env
PASSARGAD_SUB_URL=https://your-passargad-panel.example.com/sub/xxxxxxxx
GITHUB_TOKEN=ghp_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
GITHUB_OWNER=your-github-username
GITHUB_REPOSITORY=your-repo-name
GITHUB_BRANCH=main
GITHUB_FILE=unlimited.txt
TIMEOUT=15
```

| متغیر | توضیح |
|---|---|
| `PASSARGAD_SUB_URL` | آدرس ثابت اشتراک پنل پاسارگاد (محرمانه) |
| `GITHUB_TOKEN` | توکن دسترسی شخصی گیت‌هاب |
| `GITHUB_OWNER` | نام کاربری یا سازمان صاحب مخزن |
| `GITHUB_REPOSITORY` | نام مخزن گیت‌هاب |
| `GITHUB_BRANCH` | نام برنچ هدف (پیش‌فرض: `main`) |
| `GITHUB_FILE` | نام فایل مقصد در مخزن (پیش‌فرض: `unlimited.txt`) |
| `TIMEOUT` | حداکثر زمان انتظار هر درخواست شبکه (ثانیه) |

## نحوه اجرا

اجرای دستی برنامه:

```bash
cd /opt/subsync
source venv/bin/activate
python3 sync.py
```

```

[INFO] در حال بررسی SHA256...
[INFO] تغییرات شناسایی شد.
```

## نحوه تست

### تست دستی سریع

```bash
python3 sync.py
echo "کد خروجی: $?"
```

کد خروجی `0` به معنای اجرای موفق (با یا بدون تغییر) و کد `1` به
معنای بروز خطا در یکی از مراحل است.

### تست با مقادیر نامعتبر

برای اطمینان از رفتار صحیح در برابر خطا، می‌توانید موقتاً یک مقدار
اشتباه (مثلاً یک `PASSARGAD_SUB_URL` نادرست) در `.env` قرار دهید و
اجرا کنید؛ باید پیام `[ERROR]` مناسب چاپ شود و برنامه با کد خروجی
`1` (و بدون traceback خام) متوقف شود.

### بررسی فایل لاگ

```bash
tail -f logs/sync.log
```

## پیکربندی Cron برای اجرای خودکار

برای اجرای خودکار هر ۵ دقیقه، ابتدا crontab کاربر مربوطه را ویرایش کنید:

```bash
crontab -e
```

و خط زیر را اضافه کنید:

```
*/5 * * * * /opt/subsync/venv/bin/python3 /opt/subsync/sync.py >> /opt/subsync/logs/cron.log 2>&1
```

اگر از محیط مجازی استفاده نمی‌کنید و پایتون سیستم را مستقیماً به
کار می‌برید:

```
*/5 * * * * /usr/bin/python3 /opt/subsync/sync.py
```

> توصیه می‌شود مسیر کامل پایتون و اسکریپت را همیشه به‌صورت absolute
> path در crontab بنویسید، چون محیط اجرای cron با محیط ترمینال
> معمولی متفاوت است.

## نکات امنیتی

- هیچ مقدار حساسی (توکن گیت‌هاب یا آدرس اشتراک پاسارگاد) در کد
  hardcode نشده است؛ همه از `.env` خوانده می‌شوند.
- فایل `.env` در `.gitignore` قرار دارد و هرگز نباید commit شود.
- در هیچ بخشی از لاگ‌ها، مقدار توکن یا آدرس اشتراک چاپ نمی‌شود.
- درخواست‌های شبکه‌ای دارای timeout مشخص (پیش‌فرض ۱۵ ثانیه) و
  حداکثر ۳ بار تلاش مجدد در صورت خطای موقت هستند.
- قبل از هرگونه آپلود، محتوای جدید اعتبارسنجی می‌شود تا هیچ‌گاه
  محتوای خالی یا نامعتبر جای‌گزین فایل معتبر قبلی روی گیت‌هاب نشود.

## عیب‌یابی (Troubleshooting)

| مشکل | راه‌حل احتمالی |
|---|---|
| `[ERROR] متغیر محیطی اجباری ... تعریف نشده است` | بررسی کنید فایل `.env` ساخته شده و تمام مقادیر اجباری پر شده باشند. |
| `[ERROR] Timeout در دانلود سابسکریپشن` | اتصال شبکه سرور را بررسی کنید یا مقدار `TIMEOUT` را افزایش دهید. |
| `[ERROR] محتوای سابسکریپشن نامعتبر یا خالی است` | آدرس `PASSARGAD_SUB_URL` را در پنل پاسارگاد بررسی و اعتبار اشتراک را تأیید کنید. |
| `[ERROR] GitHub API رد کرد / خواندن فایل فعلی ناموفق بود` | بررسی کنید `GITHUB_TOKEN` معتبر است و دسترسی Read/Write به مخزن دارد. |
| `[ERROR] درخواست به‌روزرسانی توسط GitHub رد شد` | بررسی کنید نام مخزن، owner و برنچ در `.env` صحیح باشند. |
| کرون اجرا نمی‌شود | مسیر absolute پایتون و اسکریپت را در crontab بررسی کنید و خروجی را به یک فایل لاگ هدایت کنید تا خطا دیده شود. |
| نیاز به بررسی وضعیت کلی سرویس | فایل `logs/sync.log` را بررسی کنید؛ تمام مراحل اجرا با برچسب زمانی در آن ثبت می‌شود. |

## دریافت آدرس نهایی برای مشتریان

پس از اولین اجرای موفق، آدرس Raw فایل گیت‌هاب (که باید به مشتریان
داده شود) به این شکل خواهد بود:

```
https://raw.githubusercontent.com/<GITHUB_OWNER>/<GITHUB_REPOSITORY>/<GITHUB_BRANCH>/<GITHUB_FILE>
```

این آدرس ثابت است و مشتریان می‌توانند آن را مستقیماً در
v2rayNG، Hiddify، Clash یا Streisand به‌عنوان لینک اشتراک وارد کنند،
بدون اینکه هیچ‌گاه از وجود پنل پاسارگاد در پس‌زمینه مطلع شوند.
